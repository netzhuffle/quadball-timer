# Oxlint configuration and plugin selection

Issue #332, evaluated on 2026-09-20 at base `e288b0a8b87c8143a9d3788c818b094ec442f620`, Darwin arm64, Bun 1.4.2, Oxlint 1.82.0, and oxlint-tsgolint 7.0.2001. This does not modify or resolve #231 and does not qualify the React Compiler evaluation in #327.

## Initialization and effective behavior

The installed `bunx --bun oxlint --help`, `--rules --format=json`, `--print-config`, and `node_modules/oxlint/configuration_schema.json` were inspected before `bunx --bun oxlint --init`. Initialization produced the local schema reference, explicit TypeScript/Unicorn/Oxc plugins, correctness errors, empty rules, and `builtin` environment. The pre-initialization effective configuration contained 111 warning-level rules. Review retained the generated correctness category as errors and added only the plugins and exceptions below; no all-rules or suspicious-category blanket was adopted.

`.oxlintrc.json` is now the source of truth for plugins, rule severity, `docs/**` exclusion, type-aware analysis, type checking, and warning denial. The scripts retain Bun execution, agent diagnostics, and the ordinary `lint:fix` → `format` → `lint` workflow. Source discovery remains the repository root and existing ignore behavior: both the initial probe and final run scanned 312 files, including application, ordinary tests, scripts, and build code. Documentation remains excluded. There is no new browser/server/test directory exclusion or dependency change.

Oxlint bundles native implementations rather than loading the matching ESLint npm packages. Its installed help exposes ESLint core plus TypeScript, Unicorn, Oxc, React, React-perf, imports, JSX accessibility, Jest, Vitest, JSDoc, Node, Promise, Next.js, and Vue; core/TypeScript/Unicorn/Oxc are default enabled. Setting `plugins` replaces the defaults, so those three explicit defaults are retained. The React plugin includes hooks; `react/rules-of-hooks` is pedantic, so enabling correctness alone does **not** select it. It is explicitly enabled, along with the suspicious `import/no-self-import` rule.

The separate `jsPlugins` mechanism is alpha and uses ESLint v9-compatible APIs. It does not support type-aware external rules or custom parsers/file formats, and older ESLint APIs can be incompatible. No external plugin or experimental JS/TS configuration is needed. See [bundled plugins](https://oxc.rs/docs/guide/usage/linter/plugins.html), [JS-plugin limitations](https://oxc.rs/docs/guide/usage/linter/js-plugins.html), and [configuration](https://oxc.rs/docs/guide/usage/linter/config.html). The installed version's schema and rule inventory remain the authority for this selection.

## Diagnostic-based decisions

| Plugin | Decision and evidence |
| --- | --- |
| TypeScript, Unicorn, Oxc, core | Retain existing correctness coverage and both type modes. The final full-source run has no diagnostics; no baseline rule is removed. |
| React and hooks | Enable correctness plus Rules of Hooks. The broad probe found 12 exhaustive-dependency diagnostics: missing audit filters, an unnecessary Pitch Manager scope dependency and missing injected fetch, Controller subscription/foreground callbacks, Event Admin invalidation and initial admission, Technical Admin secret ownership and initial load, and Ad Hoc timer cleanup/measurement. Resolve these through stable callbacks, Effect Events for explicit effect-owned lifetimes, complete reactive dependencies, and capturing the cleanup-owned timer object. No blanket hooks suppression or dependency autofix is used. Other zero-diagnostic correctness rules remain enabled, including JSX key/prop checks and compiler-derived checks in that category. This is a lint decision, not a compiler performance or safety claim. |
| React compiler-derived exceptions | Defer exactly `refs` (20 diagnostics), `set-state-in-effect` (12), and `use-memo` (1). Examples include request/query refs in the audit browser and external-authority synchronization in effects. These suggest an architectural lifecycle/memoization refactor, not a safe automatic dependency repair. They are experimental analysis and are not prerequisites for ordinary React rendering. Revisit with measured compiler adoption work; no other React family is switched off. |
| JSX accessibility | Enable correctness. Fix the unnamed restore trigger, remove redundant region role, mark the Event QR backdrop as presentation, and remove redundant dialog mouse propagation interception (the backdrop already checks target equality). Keep keyboard/dialog behavior and domain assertions. Defer only `prefer-tag-over-role`: its 21 findings include replacing live status containers with `output`, custom dialogs with `dialog`, and a group with several unrelated suggested elements. Such replacements change semantics/behavior and do not establish an accessibility defect. |
| Imports | Enable correctness (`default`, `namespace`) and no-self-import. Actual Bun aliases, dynamic routes, assets and builtin imports produced no findings. Do not enable style/order constraints or a blanket Node module ban in this full-stack Bun project. |
| Jest / Vitest | Defer: the actual `bun:test` suite produces no plugin findings, but this is not evidence of test lint coverage. A disposable import-based fixture with `test.only` and an uncalled matcher emitted no Jest/Vitest findings with `bun:test`; the identical fixture imported from `@jest/globals` emitted both focused-test and invalid-expect diagnostics. Both emitted the ordinary unused-expression finding. Do not introduce Jest globals or rewrite Bun imports to trick the analyzer. No test plugin is claimed to protect Bun tests. |
| React-perf | Defer. Probing its three JSX allocation rules produced 397 function, 33 object, and 15 array findings, including ordinary event handlers in the timeline browser harness. An allocation is not measured wasted rendering; wholesale memoization would obscure dependencies and belongs to measured performance work. |
| Node, Promise, JSDoc | Probed their correctness rules against the real tree: no additional diagnostics. Defer until a concrete gap justifies them; Node policy is not automatically Bun policy, and the existing type-aware promise checks remain active. |
| Next.js, Vue | Defer: this is Bun HTML/React, with neither framework nor corresponding file format. |

Three narrowly documented inline exceptions remain for newly selected accessibility checks: the labelled overflow timeline needs a keyboard tab stop; penalty cards receive active handlers, role and tab stop only when editable (the analyzer cannot establish that conditional relationship); and the Ad Hoc QR dialog's backdrop click supplements its existing Escape/Close keyboard controls. No test assertions, sequence counts, or timeouts were changed.
